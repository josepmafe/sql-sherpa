# ui-2 — Lineage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Lineage screen: the dbt graph as a flowchart that shows names and SQL, never data, with the last full prod build's status on every node. A person can follow a table back to its sources, see what a change would reach (selecting a node highlights all its ancestors and descendants and dims the rest), and find which node a failing test belongs to.

**Architecture:**
- **Backend (`sherpa_ui`):**
  - `lineage/` turns `manifest.json` into a graph and evaluates a small dbt selector subset on it. Both are pure.
  - `build/` reads the last full prod build from `ops.dbt_run_results`.
  - Two endpoints (`/api/lineage`, `/api/lineage/nodes/{unique_id}`) combine the three.
- **Frontend:**
  - A Lineage screen with three modes that all write one dbt selector into the URL.
  - ELK lays the graph out left to right by layer, and React Flow draws it.
  - A node panel shows the SQL, columns, tests and last build.
- **Cross-links:** the Explorer's disabled "Open in Lineage" buttons come alive, and Lineage opens a mart in the Explorer.

**Tech Stack:** `@xyflow/react` (React Flow 12) and `elkjs`, added to the frontend; nothing new in Python. FastAPI, psycopg, Mantine, TanStack Query and Vitest as in ui-1.

**Spec:** `docs/superpowers/specs/2026-10-24-sql-sherpa-ui-design.md`: §3 (artifacts, build status), §4 (API), §6.5 (Lineage), §8 (testing), §10 (the ui-2 row). Data platform spec §8, "Added by ui-1" (`ops.dbt_run_results`). **`CLAUDE.md` is binding.** The decisions this plan makes are written into the UI spec in the same commit; the spec is the reference.

**Base:** `main` with ui-1. The plan assumes nothing about data-platform-3, which may merge before or after: snapshots, unit tests and analyses are handled generically, and no test counts nodes.

**Model selection:** every task names its implementer and reviewer models. Dispatch exactly those. Fix rounds 4–5 go one tier up (`haiku` → `sonnet` → `opus`). The final whole-branch review is Task 8's panel.

## Global Constraints

- **Incremental commits (CLAUDE.md):** each task adds only the files, packages and config it uses. Every commit leaves `make lint` and `make test` green.
- **Layout:** `ui/backend/src/sherpa_ui/lineage/`, `build/` and `api/lineage.py`; `ui/frontend/src/screens/lineage/`; tests mirror the packages. No new Make target, setting, environment variable or compose change: the `ui` service already mounts `data-platform/dbt`, so it reads `target-prod/compiled/` too.
- **Names and SQL only, never data.** Lineage runs no user SQL. Its one database read is a fixed query on `ops.dbt_run_results` over a short read-only connection as `sherpa_ui`.
- **A worktree has none of the gitignored files.** Before Task 1, copy `.env` from the main checkout, then run `uv sync`, `cd ui/frontend && npm ci` and `make build-prod`. The last one writes this checkout's `target-prod/` (the artifacts are per checkout) and rebuilds the shared `sherpa` prod schemas, which is what the compose `ui` reads.
- **Offline:** `elkjs` is bundled (no CDN, no remote worker), and React Flow brings no remote asset.
- **Accessibility:** status is an icon and a text label as well as a colour. Nodes are reachable by keyboard.
- **Browser storage:** none. The URL is the state.
- **Tests:** backend units and integration (`warehouse` marker) in pytest, frontend in Vitest, end to end in Playwright (`make e2e`). The failing-node e2e check writes to the shared warehouse, so it runs only on request (Task 7).

## Review Focus

1. **A layout that finishes late:** the user changes the selector while ELK is still laying out the previous graph. The late result must not overwrite the newer one. Test: Vitest `useGraphLayout ignores a superseded layout` (Task 5).
2. **A manifest half-written by a running `make build-prod`, or missing:** the loader keeps the last graph that loaded (as `MartCatalogLoader` does, UI spec §3), and only a backend that never loaded one answers `catalog_unavailable`. Tests: `TestManifestLoader::test_keeps_the_last_graph_when_a_reload_fails` and `test_raises_when_it_never_loaded` (Task 1).
3. **Odd selectors:** empty, whitespace-only, `+`, `++a`, `a,b`, `@a`, `tag:x`, `a+b`, a 5,000-character string, a name that matches nothing. The unsupported forms answer `unsupported_selector` and list what is supported; a name that matches nothing is an empty graph, not an error; nothing is a 500. Tests: `TestSelectorEvaluator::test_unsupported_forms_name_what_is_supported` and `test_unknown_name_selects_nothing` (Task 1).
4. **Build status edge cases:** no full build recorded, the `ops` table missing, the database down, an ephemeral model, a test that touches two models, a `warn` test, an upstream failure (`skipped`), a status string dbt adds later. Tests: `TestStatusDeriver` (Task 2) and `TestLineageApi::test_graph_without_a_database_has_no_status` (Task 3).
5. **A manifest that points outside `compiled/`:** an `original_file_path` with `..` or an absolute path must not read any other file. The panel shows the raw SQL and a note. Test: `TestNodeSql::test_a_path_outside_compiled_is_not_read` (Task 3).

### Task 1: Manifest graph, loader and selector subset (pure)

**Model:** implementer `sonnet` · reviewer `sonnet` (the `dbt ls` oracle makes a wrong traversal visible)

**Files:** `lineage/manifest_loader.py`, `lineage/manifest_graph.py`, `lineage/selector.py`, tests.

**Interfaces — Produces:**
- **`Layer`** (`StrEnum`, `auto()`): `SOURCE`, `SEED`, `STAGING`, `SNAPSHOT`, `INTERMEDIATE`, `MARTS`, `EXPOSURE`, `OTHER`. The layer of a model is `fqn[1]` when it is `staging`, `intermediate` or `marts`, otherwise `OTHER`.
- **`GraphNode`** (frozen): `unique_id, name, resource_type, layer, materialization: str | None, domain: str | None, description, file_path, package_name, raw_sql: str | None, contract_enforced: bool, columns: tuple[NodeColumn, ...], parents: tuple[str, ...]`. `NodeColumn`: `name, data_type: str | None, description`.
- **`NodeTest`** (frozen): `unique_id, name, kind: Literal["generic", "singular", "unit"], column: str | None, severity: Literal["error", "warn"], counts_against: tuple[str, ...]`.
  - A generic test counts against its `attached_node`.
  - A singular test counts against every graph node in its `depends_on`.
  - A unit test counts against the node in its `depends_on` whose name is its `model`.
- **`ManifestGraph`:**
  - `from_manifest(manifest: dict[str, Any]) -> ManifestGraph`
  - `nodes: Mapping[str, GraphNode]`, `generated_at: datetime`
  - `parents(unique_id) -> tuple[str, ...]`, `children(unique_id) -> tuple[str, ...]` (graph nodes only)
  - `tests_of(unique_id) -> tuple[NodeTest, ...]`
  - `layers() -> tuple[Layer, ...]` (those present, in layer order)
- **Graph nodes:** sources, seeds, models, snapshots and exposures. Tests, unit tests, analyses and operations are not nodes. A `depends_on` entry that is not a graph node (a macro) is dropped.
- **`file_path`** is the manifest's `original_file_path` with every `\` replaced by `/`. dbt writes the path with the separator of the machine it ran on, so a manifest built on Windows has `models\marts\sales\fct_orders.sql`, which the Linux `ui` container can't open.
- **`ManifestLoader(target_path: Path)`:** `load() -> ManifestGraph`. It rebuilds when `manifest.json`'s mtime changes. A failed rebuild keeps the last graph with a warning; only a loader that never loaded one raises `CatalogUnavailable` (`sherpa_mcp.catalog`). It follows `MartCatalogLoader`'s contract (UI spec §3) and reads only the manifest.
- **`UnsupportedSelector(Exception)`** with `message` listing the supported forms.
- **`SelectorEvaluator(graph)`:** `select(selector: str) -> frozenset[str]`.
  - **Atoms:** a model, seed, snapshot or exposure name (a source table is reached only as `source:<source>.<table>`, as in dbt), `source:<source>`, `source:<source>.<table>`, `exposure:<name>`, `config.meta.domain:<domain>`.
  - **Operators:** `+atom`, `atom+`, `n+atom`, `atom+n+`, `n+atom+m`.
  - **Unions:** atoms separated by whitespace.
  - An empty or blank selector selects every node.
  - Anything else raises `UnsupportedSelector`: intersections (`,`), `@`, other methods (`tag:`), selectors over 1,000 characters, and a bare name that dbt reads as a group or a test: the package and the first folder of every non-source node (`fqn[:-1][:2]`), and the names of tests and analyses (a graph node named like a test or an analysis still selects itself). The hint points to the layer filter. A deeper folder name (`sales`, `shop`) is no group in dbt and selects nothing.
  - A well-formed atom that matches nothing selects nothing.

  - `TestManifestLoader`: `test_reloads_when_the_file_changes`, `test_keeps_the_last_graph_when_a_reload_fails` (truncated JSON), `test_raises_when_it_never_loaded` (missing file).

### Task 2: Last full build and node status

**Model:** implementer `sonnet` · reviewer `sonnet` (a table of rules, tested row by row)

**Files:** `build/build_status.py`, `lineage/node_status.py`, tests.

**Interfaces — Produces:**
- **`NodeResult`** (frozen): `unique_id, resource_type, status: str, failures: int | None, execution_time_s: float | None, message: str | None`.
- **`LastFullBuild`** (frozen): `invocation_id, started_at: datetime, results: Mapping[str, NodeResult]`, with `node_count` (the number of rows).
- **`BuildStatusReader(settings: UiSettings)`:**
  - `last_full_build() -> LastFullBuild | None`
  - It runs one fixed statement over a short autocommit connection (`settings.ui_conninfo()`): the rows of the newest `invocation_id` with `target_name = 'prod'`, `command = 'build'` and `is_full_run`.
  - It returns `None` for no such invocation and for a missing `ops` schema or table (`UndefinedTable`, `InvalidSchemaName`).
  - It raises `BuildStatusUnavailable` when the database cannot be reached.
  - Blocking: call it from a worker thread. Its statement is also the one ui-3 reuses for the data-status strip.
- **`NodeStatus`** (`StrEnum`): `OK`, `WARNED`, `FAILED`, `SKIPPED`, `NOT_IN_BUILD`, `INLINED`, `NO_BUILD`, `NONE`. **`TestOutcome`:** `PASSED`, `WARNED`, `FAILED`, `SKIPPED`, `NOT_RUN`.
- **`StatusDeriver(graph, build: LastFullBuild | None)`:** `node_status(unique_id) -> NodeStatus`, `test_outcome(test: NodeTest) -> TestOutcome`. The rules are UI spec §6.5:
  - A test row: `pass` → `PASSED`; `warn` → `WARNED`; `fail`, `error`, `runtime error` → `FAILED`; `skipped` → `SKIPPED`; no row → `NOT_RUN`.
  - A model, seed or snapshot, first match wins:
    1. own row `error`, `runtime error` or `partial success` (dbt treats it as a failure and skips the dependents), or any counted-against test `FAILED` → `FAILED`
    2. own row `skipped` → `SKIPPED`
    3. any test `WARNED` → `WARNED`
    4. own row `success` or `no-op` → `OK`
    5. no row → `INLINED` for an ephemeral model, otherwise `NOT_IN_BUILD`
  - Sources and exposures are always `NONE`.
  - With `build is None`, every other node is `NO_BUILD`.
  - A status string outside these lists is logged at warning level and treated as no row.

- [ ] **Step 1: Tests first.**
  - `TestStatusDeriver`: one test per rule above, each named for its rule, plus:
    - `test_a_failing_singular_test_fails_every_model_it_depends_on`
    - `test_a_warning_is_not_a_failure`
    - `test_a_failed_model_marks_downstream_skipped_not_failed`
    - `test_unknown_status_is_logged_and_treated_as_no_row`
    - `test_no_build_gives_no_status_not_not_in_build`
  - `TestBuildStatusReader` (marker `warehouse`, as admin it writes rows into a **throwaway database** created by a fixture, never into `sherpa`; the fixture creates the `ops.dbt_run_results` table with the hook's columns and grants `sherpa_ui` `usage` on `ops` and `select` on the table):
    - `test_returns_the_newest_full_prod_build_only` (a partial prod build, a dev build and an older full one are ignored)
    - `test_none_without_a_full_build`
    - `test_none_when_ops_is_missing`
    - `test_unavailable_when_the_database_is_down`
- [ ] **Step 2:** Run (FAIL) → implement → run (PASS) → `make lint`. Commit `feat: last full build reader and lineage node status`.

### Task 3: Lineage service and API

**Model:** implementer `sonnet` · reviewer `sonnet`

**Files:** `lineage/node_sql.py`, `lineage/lineage_service.py`, `api/lineage.py`, wiring in `app.py`, the error codes in `api/errors.py`, `ui/frontend/src/api/schema.d.ts` (generated), tests.

**Interfaces — Produces:**
- **`NodeSql(target_path: Path)`:** `compiled(node: GraphNode) -> str | None`.
  - The file is `<target_path>/compiled/<package_name>/<file_path>` when the node's file ends in `.sql`.
  - For a node defined in YAML (a snapshot) it is `<target_path>/compiled/<package_name>/<file_path>/<name>.sql`.
  - It joins the forward-slash `file_path` (Task 1), so it finds the file whatever OS wrote the manifest.
  - The resolved path must stay inside `<target_path>/compiled`; otherwise or when the file is missing, `None`.
- **`LineageService(loader: ManifestLoader, builds: BuildStatusReader, node_sql: NodeSql)`**, blocking:
  - `graph(select: str, layers: frozenset[Layer] | None, failing_only: bool) -> LineageGraph`
  - `node(unique_id: str) -> NodeDetails | None`
- **API models** (frozen Pydantic):
  - `LineageNode`: `unique_id, name, resource_type, layer, materialization, domain, status: NodeStatus, failing_tests: int`
  - `LineageEdge`: `source, target` (the parent and the child)
  - `BuildInfo`: `state: Literal["ok", "no_build", "unavailable"], started_at: datetime | None, node_count: int | None`
  - `LineageGraph`: `nodes, edges, build, layers_available: list[Layer]`, built as:
    1. select the node set
    2. drop the layers not asked for
    3. keep only `FAILED` nodes when `failing_only`
    4. keep the edges whose both ends survived (no bridging)
    - `layers_available` always lists the layers of the whole manifest, so the filter doesn't shrink.
  - `NodeDetails`: the node's fields, `raw_sql`, `compiled_sql`, `sql_note: str | None` (set when the compiled file is missing), `columns`, `tests: list[TestInfo(name, kind, column, severity, outcome)]`, `build: NodeBuildInfo | None(status, execution_time_s, message)`, `is_mart`.
- **Routes** (`/api/lineage`, tag `lineage`): `GET ""` with `select` (default empty, at most 1,000 characters), `layers` (comma list; an unknown layer is `invalid_request`) and `failing_only`; `GET "/nodes/{unique_id}"`.
- **Errors:**
  - `unsupported_selector` (422): the message lists the supported forms.
  - `node_not_found` (404).
  - A manifest that never loaded is the existing `catalog_unavailable` (503).
  - A `BuildStatusUnavailable` is not an error: `build.state = "unavailable"` and every node `NO_BUILD`.
  - Add the codes to `ERROR_STATUS_DESCRIPTIONS`.

- [ ] **Step 1: Tests first.**
  - Units (fake loader, builds and SQL reader): `TestLineageService` for each filter and for `failing_only` keeping only failed nodes and their mutual edges; `TestNodeSql`:
    - `test_reads_a_model_file`
    - `test_reads_the_file_of_a_manifest_written_on_windows` (a graph built from backslash paths)
    - `test_reads_a_yaml_defined_node`
    - `test_a_path_outside_compiled_is_not_read`
    - `test_missing_file_is_none`
  - `TestLineageApi` (`TestClient`):
    - `test_unsupported_selector_is_422_with_the_supported_forms`
    - `test_unknown_node_is_404`
    - `test_graph_without_a_database_has_no_status`
    - `test_layers_filter_drops_edges_to_hidden_nodes`
    - `test_unknown_layer_is_invalid_request`
  - `warehouse` (the real prod manifest and `sherpa_ui`):
    - `test_whole_project_has_a_mart_with_its_sources_upstream`
    - `test_node_panel_has_compiled_sql_for_fct_orders`
    - `test_ephemeral_model_is_inlined`

### Task 5: The graph canvas — ELK layout, React Flow, node styling

**Model:** implementer `sonnet` · reviewer **`opus`** (the late-layout race in `useGraphLayout`, and React Flow in jsdom)

**Files:** `layout.ts`, `useGraphLayout.ts`, `highlight.ts`, `GraphNode.tsx`, `LineageCanvas.tsx`, wiring in `LineageScreen.tsx`, `tests/setup.ts` (the jsdom shims React Flow needs: `ResizeObserver`, `DOMMatrixReadOnly`), tests.

**Interfaces — Produces:**
- **`layoutGraph(nodes: LayoutNode[], edges: LayoutEdge[]) -> Promise<Map<string, Point>>`** (pure apart from `elkjs`): the ELK `layered` algorithm, direction right, with partitioning so the columns are the layers: sources and seeds, then staging and snapshots, then intermediate, marts, exposures; `OTHER` sits with intermediate. Node size constants `NODE_WIDTH` and `NODE_HEIGHT`.
- **`useGraphLayout(nodes, edges) -> {positions: Map | undefined; state: "idle" | "laying-out" | "ready" | "error"}`:** runs `layoutGraph` when its inputs change, and **discards the result of any run that has been superseded** (compare a run token). An `error` keeps the previous positions.
- **`GraphNode`:**
  - name, a layer colour (the Mantine palette, AA contrast in light and dark), a materialization badge
  - the status: icon plus text (`failed`, `warned`, `skipped`, `ok`, "not in the last build", "inlined"; nothing for `NONE` and `NO_BUILD`)
  - failed nodes carry a red border and the failing-test count
  - nodes are focusable; a click or Enter selects one
  - a dimmed node has `data-dimmed`; its stripe, border and background fade, not its text, and it stays focusable and selectable
- **`LineageCanvas`:** React Flow in the OS colour mode, `fitView` after each layout, pan and zoom, a minimap only above 60 nodes, Zoom buttons whose fit never passes 1x, and for an empty graph an empty state that names the reason: "No node matches this selector"; "No node in the layers shown" (layer filter); with "Failing only" on, "Nothing failed in the last full build", "No failed node in the layers shown" (layer filter) or "No build status to filter on" (no build, or unreadable). The nodes are in the DOM left to right, then top to bottom, so Tab follows the screen.
- **`relatedNodes(edges: LayoutEdge[], id: string) -> {nodes: Set<string>; edges: Set<string>}`** (`highlight.ts`, pure): the node, every ancestor and every descendant reachable over the given edges, and the edges among them. It gets only the edges shown, so a chain through a hidden layer ends there, like the edges themselves.
- **Selecting a node** (UI spec §6.5) writes `node=` to the URL. The canvas then emphasises the node, highlights `relatedNodes` (their nodes and edges) and dims everything else. Esc, the panel's close button or a click on the background clears `node`. A `node` that isn't in the graph (after a selector change) clears itself. The highlight is computed in the browser and needs no request.

- [ ] **Step 1: Vitest first.**
  - **`layoutGraph`** (runs `elkjs` for real in Node):
    - `puts each layer in its own column, left to right`
    - `lays out a graph with a single node`
    - `lays out an empty graph`
  - **`useGraphLayout`:**
    - `ignores a superseded layout` (the first run is made to finish after the second)
    - `keeps the previous positions when a layout fails`
  - **`LineageCanvas`:**
