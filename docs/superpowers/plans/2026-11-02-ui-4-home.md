**Goal:** The Home screen at `/`: five headline tiles, a 26-week trend and a data-status strip, read live from the marts, `ops.dbt_run_results` and `sources.json`, with Home declared as the dbt exposure `sherpa_home`.

**Architecture:**
- **Queries.** Every Home figure is a curated SQL query in `ui/backend/src/sherpa_ui/home/home_queries.yaml`, run through the existing `QueryRunner` (guard, `sherpa_ui`, row cap), so Home reads exactly what a person could query.

- **Frontend.** The screen renders the answer; it holds no business rules.

## Global Constraints

- **Metric definitions** (data platform spec §6.6, UI spec §6.2):
  - non-cancelled orders by `order_date`
  - the refund rate's refunds by `refund_date`
  - new customers via `fct_orders.is_first_order`, deleted customers included
- **Windows:** the last 30 days ending on `as_of_date` = `order_date` in (`as_of − 30`, `as_of`]; the 30 days before = (`as_of − 60`, `as_of − 30`]. `as_of_date` = `max(order_date)` over `marts.fct_orders` (data platform spec §6.5), never `now()`.

**The YAML** (verified at planning: every query passes the guard and runs as `sherpa_ui` in under 50 ms, and each tile matches an independent query on the shared warehouse):
- **Shape.** `period:` returns one row (`as_of_date`, `first_order_date`): `select max(order_date) as as_of_date, min(order_date) as first_order_date from marts.fct_orders`.
- **Tiles.** Each returns one row (`this_period`, `last_period`), in this order:
  - `net_revenue`: "Net revenue", currency, 0 decimals, up is good. `note`: "The previous period is shown as it stood 30 days ago, because refunds arrive up to about 7 weeks after an order, so the latest 30 days have few refunds yet and read high." The previous period is the earlier window's orders less only the refunds paid by `as_of - 30`.
  - `orders`: "Orders", count, up is good.
  - `aov`: "AOV", currency, 2 decimals, up is good.
  - `refund_rate`: "Refund rate", percent, 1 decimal, **up is not good**.
  - `new_customers`: "New customers", count, up is good.
- **Trend** returns `week_start`, `net_revenue`, `is_black_friday_week`, oldest first.
- **The SQL.** Every tile starts from `with bounds as (select max(order_date) as as_of from marts.fct_orders)` and splits the two windows with `filter (where o.order_date > b.as_of - 30)` / `<= b.as_of - 30` over `left join marts.fct_orders as o on o.order_date > b.as_of - 60 and not o.is_cancelled`:
  - **net revenue:** `coalesce(sum(o.net_revenue) filter (...), 0)`
  - **orders:** `count(o.order_id) filter (...)`
  - **AOV:** `sum(net_revenue) / nullif(count(order_id), 0)` per window
  - **refund rate:** a `refunds` CTE over `marts.fct_refunds as r on r.refund_date > b.as_of - 60 and r.refund_date <= b.as_of`, summing `revenue_amount` per window with `coalesce(…, 0)`; a `sales` CTE summing `gross_revenue` of non-cancelled orders per window; the result is `refunds.x / nullif(sales.x, 0)` per window
  - **new customers:** like orders, with the join's condition `o.is_first_order` instead of `not o.is_cancelled`
  - **trend:**
    - `bounds` joins `marts.dim_date` twice, for the weeks of `as_of` and of the first order
    - `weeks` takes the `dim_date` rows with `date_day = week_start` and `week_start` between `greatest(as_of_week - 175, first_week)` and `as_of_week`
    - `revenue` sums non-cancelled `net_revenue` by `dim_date.week_start`
    - the result is `weeks left join revenue`, with `coalesce(net_revenue, 0)`
- **Guard notes.** Postgres `date - integer` gives a date, and the guard allows `filter`, `greatest`, `nullif` and `coalesce`. No query may cast to a type outside `CAST_TYPES`, use `now()` or read a mart beyond the three.
